I wanted to understand how SIEM ACTUALLY works under the hood.

So I built my own SIEM from scratch. 🔧

Here's what most people don't realize about enterprise SIEMs:

They're not magic — they're just clever parallel pipelines.

→ Ingestors that stream logs in real-time
→ Parsers running in parallel across multiple workers
→ Indexers batching data into databases
→ Alert engines with sliding window rules

I built SIEM-Lite to simulate this exact architecture:

• 4 parallel parser workers processing logs simultaneously
• Real-time alert generation (5+ suspicious events in 60s = alert)
• Rule-based detection for SQL injection, path traversal, CMS probing
• Custom visualizations to SEE what the pipeline actually does

The result? I finally understand:
✅ Why SIEMs need distributed processing
✅ How alert rules actually work (sliding windows, thresholds)
✅ Why log enrichment matters (IP classification, user-agent parsing)
✅ How backpressure happens in queues

Reading documentation tells you WHAT.
Building it yourself teaches you WHY.
